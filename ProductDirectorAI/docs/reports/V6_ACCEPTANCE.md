## 3. 未完成 / 阻塞项（如实记录，不掩盖）

### 3.1 需要用户提供外部条件

1. **四个平台连接器没有真实授权**：`/publishing/accounts` 为空、`/publishing/jobs` 为空。真实上传、平台处理状态、最终公开链接**未被验证**；`submit_publish` 在本部署有意不发起真实上传。需要：注册应用 + 平台侧 scope 审批 + 真实账号授权（TikTok 未审核客户端只能 `SELF_ONLY`）。
2. **没有真实第三方 Webhook 接收方**：全部投递证据来自本机接收端；跨公网 TLS/DNS/代理未验证。
3. **没有商业配音音色与授权 BGM**：宇航员广告用的是离线 espeak 预览音色、无 BGM（Manifest 如实标 disabled）。

### 3.2 需要负责人人工完成

4. V3 / V4 / V5 三份 ACCEPTANCE 草稿的人工复核（V6 依赖的 V1–V5 能力已具备，但阶段门未关闭）。
5. V5 的 10 条有权使用的参考片 + 人工标注夹具。
6. 浏览器人工走查（本环境无浏览器；前端已 build 且接口冒烟通过，但点击级走查未做）。
7. 宇航员广告的**产品保真**未达 brief（单视图重建无贴图、产品悬空、预览音色、无 BGM）——需要官方带贴图模型 / 多视图重建 / H3 产品替换参考视频 / 商业配音与授权 BGM 之一。

### 3.3 已知的产品边界（代码里已明示，不视为缺陷）

8. 成本账本中自管 GPU/CPU 为**内部估算**，不是真实云账单；无多币种换算；无导出报表。
9. Webhook 交付为**至少一次**，不保证顺序；Outbox/投递记录/账本/包目录**无自动保留策略**。
10. 幂等键强制范围目前是 Automation 调用；浏览器会话路径沿用 CSRF + 请求体幂等键。
11. 调度与投递 tick 需要 systemd timer 或常驻 Worker（手册已给 unit 模板），产品内无常驻调度进程。
12. 负载实测基于 540×960/6s 计划、单机 2 Worker；未做 1080p 吞吐、多机 Worker、长时间浸泡测试。

## 4. 发布建议（Release Recommendation）

- **可发布的形态**：单机私有部署，覆盖「Profile → 批量生产 → 后期 → QA → 发布包 → 成本/自动化/事件」全链路；任何真实平台投稿保持 BLOCKED，直到用户提供授权。
- **发布前必须完成的动作**（按顺序）：
  1. 负责人复核本文档第 3.2 节的人工项；
  2. 按 [运行手册](RUNBOOK_V6.md) 配置 Worker/调度/投递 systemd 单元与备份；
  3. 若本次发布需要真实投稿：提供平台应用凭据与账号授权，并按 `docs/integrations/*.md` 逐平台完成真实链路验收（含私密可见性 ≠ 公开权限的区分）。
- **不建议**：在没有真实授权证据的情况下对外声称"已支持一键发布到 TikTok/YouTube/Instagram/Facebook"。
