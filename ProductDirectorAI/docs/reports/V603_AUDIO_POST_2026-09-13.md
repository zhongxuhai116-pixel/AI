## 1. 交付物

### 1.1 模块 `apps/api/productdirector_api/audio_post.py`

| 能力 | 实现与诚实边界 |
| --- | --- |
| 响度测量 | `measure_loudness`：ffmpeg `ebur128(peak=true)` → 综合 LUFS / LRA / 真峰值；`loudness_verdict` 按**产品默认** −16 LUFS ±1.5 LU、真峰值 ≤ −1 dBTP 判定，偏差如实列出（注明「不代表平台官方要求」） |
| 混音 | `mix_tracks`：旁白/BGM 独立轨 → 增益 → **ducking（旁白优先）** → `loudnorm` 归一 → `alimiter` 真峰值限制 → 48kHz 立体声；开关语义明确：`None` = 自动取最新配音、`""` = **显式关闭该音轨** |
| ducking | `sidechaincompress` + **自动阈值**：从**实测旁白电平**推导（−6 dB 余量、限幅 −45…−12 dB），因为固定阈值在真实人声上不可靠（实测人声均值 ≈ −23.9 dBFS，而 ffmpeg `sine` 等测试信号远低于满刻度）；阈值来源与实测值都写入报告 |
| ducking 验收 | `verify_ducking`：把 **ducking 前后的音乐分支**分别渲染，在**语音段与停顿段**两个窗口测同一频段电平 —— 因为成品响度归一会把跨文件/跨频段差异抵消，只有在分支层才测得真实压低量 |
| 频谱测量 | `measure_band_level` / `measure_window_band_level`（bandpass + volumedetect）：用于在响度归一后区分音轨来源 |
| 语音段检测 | `detect_speech_windows`：ffmpeg `silencedetect` 求语音段与停顿段（与 V6-02 字幕对齐同一实测口径） |
| 时长适配 | `adapt_plan_duration`：三种策略 + `fail_and_review`；**接触镜头（press_button / single_punch_target）绝不改动**，延长只落在非接触镜头且受 `extend_max_frames` 与 Profile 时长上限双重约束；调速超范围直接拒绝；改文案不改视频 |
| 编码 | `encode_rendition`：按 Profile 规格编码（h264/hevc、mp4/mov、fps、分辨率），可选混音轨，ffprobe 复核分辨率/音频流；**构图策略感知**：`letterbox`（等比补边）/ `crop_if_safe`（居中裁切）/ `reframe_3d`（**拒绝**：需 3D 重构图，不能用 2D 缩放替代） |
| 封面 | `make_thumbnail`：真实抽帧（非占位图） |

### 1.2 API

| 方法与路由 | 行为 |
| --- | --- |
| `GET/POST /api/v1/music-assets`、`GET /music-assets/{id}/content` | BGM 素材库：**必须带 `license_ref`**（缺失 422），记录是否允许商业使用；原文件默认不进发布包 |
| `POST /api/v1/runs/{id}/audio/mix`、`GET /audio/mixes/{id}/content` | 真实混音：旁白优先 + 响度达标判定；商业用途 Profile（Ads 素材/Listing）遇到非商用 BGM → **422 `MUSIC_NOT_COMMERCIAL`**；两条音轨都关闭 → 422（不生成静音混音） |
| `POST /api/v1/runs/{id}/audio/adapt` | 配音过长适配决策（三种策略 + 约束记录） |
| `POST /api/v1/video-sources` | 登记真实渲染 Master（保留来源链） |
| `POST /api/v1/runs/{id}/outputs`、`GET /outputs/{id}`、`GET /outputs/{id}/content` | 编码成片（可烧录字幕）+ 无字幕 Master + 封面；每条 rendition 记录 **lineage**（Master sha256、混音 sha256、Profile 版本与 payload hash、构图策略、响度复测） |

## 4. 如实未完成 / 边界

1. **BGM 素材是合成测试信号**：本机没有可核验授权的音乐库，因此 ducking/响度/许可闸门用合成和弦床验证，并在报告与素材名中明确标注「非授权音乐」。真实发行必须由负责人上传**有明确许可**的 BGM（接口与闸门已就绪）。
2. **响度目标为产品默认**：−16 LUFS ±1.5 LU / −1 dBTP 是本产品设置，未核验任何平台的官方响度要求；Profile 级独立设置字段已存在（`mix`），但未逐平台核验。
3. **时长适配只执行"延长非接触镜头"**：调速与改文案返回决策让上游处理（V6-02 已支持改写文案与重新合成）；延长后的**参考重演计划需要重新生成映射**才能渲染（报告中已提示，映射一致性由 V5 规则约束）。
4. **编码未做平台专属码率/封装核验**：使用 h264/hevc + mp4/mov 的通用参数，Profile 的 `bitrate_policy` 仍未核验（V6-C 前必须查官方资料）。
5. **响度/真峰值只做静态复测**：未做逐帧/分段的动态一致性检查，也未实现平台特定的响度门限。
6. **前端未接入**：BGM/混音/成片界面属于 V6-09 总控台；发布包（含字幕侧车、文案、封面、Manifest）属于 V6-05。

## 5. 本轮修好的真实缺陷（全部来自真实验证）

1. **滤镜图 pad 被消费两次**：旁白同时作为 sidechain 与混音输入 → 需要 `asplit`。
2. **`aloop` 巨量缓冲导致 filter 注入失败** → 循环改在 demuxer 层（`-stream_loop`）。
3. **输入索引按参数个数推算**：加入 `-stream_loop` 后索引错位，`[2:a]` 指向不存在的输入 → 改为显式计数。
4. **`sidechaincompress` 需要显式声道布局**（"No channel layout for input 1"）→ 两条链都加 `aformat=channel_layouts=stereo`。
5. **固定 ducking 阈值在真实人声上不生效**（人声均值 −23.9 dBFS，阈值 −18 dB 从不触发）→ 改为按实测旁白电平自动推导并记录来源。
6. **跨文件比较无法验证 ducking**（响度归一会补偿）→ 增加分支级 `verify_ducking` 验收方法。
7. **省略 `voiceover_id` 会自动带上最新配音**，导致「只要 BGM」无法表达 → 改为 `None`=自动、`""`=显式关闭。
8. **跨比例编码会拉伸画面** → 按 Profile 的 `crop_policy` 实现 letterbox / 居中裁切，`reframe_3d` 明确拒绝。
9. **PostgreSQL schema 未同步**（V6-02 教训重演风险）→ 本轮新表同时写入 `db/schema.postgres.sql` 并随部署更新。
