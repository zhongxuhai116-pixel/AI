## 2. 既定关闭条件仍未满足

这些检查来自上轮已明确的“冻结计划帧数、共同缺尾帧、预览与全片区分、可信 Alpha/Mask 对应”要求，不是改变验收标准。

| 边界 | 复现 | 当前实际 | 需要整改 |
| --- | --- | --- | --- |
| 三通道共同缺中间帧 | 产品/Mask/背景都只有帧 1、3 | exit 0、passed=true、输出 2 帧 | 校验预期连续帧范围，不能只比较三个集合是否相等 |
| 三通道共同缺尾帧 | 目标 3 帧，三组输入均仅有 1、2 | exit 0、passed=true、输出 2 帧；CLI 没有计划/预期帧数参数 | 显式接收冻结计划或可信的预期帧数，不能从已有文件推测完整性 |
| 抽样预览冒充通过 | 正常 3 帧输入加 `--limit 1` | exit 0、passed=true、输出 1 帧 | 预览可运行成功，但报告必须区分 PREVIEW_ONLY 与完整 PASS |
| 黑色产品配空遮罩 | 产品 RGB 全零，但可信 PNG Alpha 有可见区域；Mask 全空 | exit 0、passed=true、pixel_lock_ok=true | 依据可信 Alpha 与镜头合同判断可见性；RGB=0 不等于产品不存在 |

证据：[boundaries.json](../../var/acceptance/2026-09-12-recheck-091526/boundaries.json)，复现入口为同目录 `boundaries.py`。共同缺尾帧的“目标 3 帧”是本验收输入合同；当前 CLI 无法表达该合同本身也是缺口。

代码定位：

- `scripts/strict_composite.py:126–134` 使用三组交集为基准；`common_frames - frame_set` 永远为空，导致“缺帧”分支无法触发。
- 因此背景缺第 3 帧时，实际报错为 `product 有多余帧：[3]`、`mask 有多余帧：[3]`，而不是定位背景缺帧。虽然最终被拒绝，错误定位仍不满足整改要求。
- `scripts/strict_composite.py:138–140,188` 截取 limit 后仍按普通流程标记 passed。
- `scripts/strict_composite.py:168–169` 用非零 RGB 判可见性，读取产品时丢弃了可信 Alpha。
