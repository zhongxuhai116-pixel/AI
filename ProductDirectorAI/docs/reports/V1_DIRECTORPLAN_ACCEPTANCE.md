# V1 DirectorPlan 相机语义验收

日期：2026-09-11
结论：GLB 的镜头编辑、计划冻结与 Blender 相机动作 PASS；图片预演也会从同一冻结计划编译可见的 2D 分镜 PASS。

## 改动

- 前端允许编辑每个镜头的相机模板、焦距和时长，并显示总帧数。
- API 拒绝不等于 144 帧的三镜头计划。
- 创建 Run 时把计划写入该作业目录；渲染器从快照读取，而不是重新读取可变的计划数据库记录。
- Blender 将 `dolly_in`、`side_track`、`hero_orbit`、`static` 及焦距/时长编译为相机关键帧。
- 图片预演将同一快照拆成三段 FFmpeg `zoompan` 片段并精确拼接为 144 帧；`hero_orbit` 在单张图片路径中是 2D 横移、纵移和缩放的视差近似，不宣称物理 3D 环绕。
- Manifest 写入冻结计划与快照 SHA-256。

## 自动检查

Python 合同测试通过 4 项：有效 144 帧计划、非法总帧数拒绝、冻结快照字段保留、图片三段滤镜合同。前端生产构建通过，Sites worker 测试 4/4 通过，API 与 Web systemd 服务均健康。
