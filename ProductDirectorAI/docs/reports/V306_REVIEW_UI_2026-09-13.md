## 2. 线上真实 E2E（live API，127.0.0.1:8000 + web 4173）

流程（全部真实 HTTP，凭证不落日志）：

1. 上传 CC0 `Camera_01_textured.glb`（2.4MB）→ 模板计划（改为 3×static 固定构图，Logo 区域按实际投影声明）→ 批准计划/产品版本；
2. `GET /plans/{id}/contracts` → 冻结合同 id；创建审核（APPROVED/cad + logo_regions）与 STRICT 保真策略；
3. `POST /runs`（require_fidelity_snapshot + 三件套绑定）→ **真实 Blender 受控渲染 144 帧**（RENDER → VERIFY → VERIFICATION_PASSED，约 90s）；
4. `GET /qa-reports?job_id=` → 报告落库：**status NOT_VERIFIED、problems=0**；color_core / edge / contour / logo / asset_hash 均 PASS（同空间对照生效），dimension / encoded_media / product_id 如实 NOT_VERIFIED；
5. 审批门：REJECTED 与 APPROVED 均 409「Manifest 缺少 QA 报告，不能批准」——验证小样（未合成/未编码）不可审批为 Strict 成果，门生效；
6. `strict-artifacts` 帧预览：product/mask frame1 → 200 image/png；composite → 404（无背景工作流未合成，如实）；EXR 通道 → 404（注明需专用查看器）。

过程中发现并修复的两个真实缺陷：

- **受控渲染小样静默跳过 QA**：无背景工作流分支直接 VERIFICATION_PASSED、无任何 QA 记录——违反主规划 §9.9（QA 必经）。修复后该分支运行真实 QA 引擎并落库（`test_controlled_verification_sample_persists_qa_report` 钉住）。
- **跨空间颜色误判**：product（AgX display PNG）与 passes/beauty（scene EXR）此前直接互比，真实数据上 color/edge/logo 全部误 FAIL（144 帧 432 个问题）。修复为同空间对照（display↔主帧、scene↔EXR），不可比时 NOT_VERIFIED；API 级故障注入测试改用同空间夹具后仍然全部触发对应失败（Logo/尺寸/错位/变色 → QA_REJECTED）。
