## 1. 交付物

### 1.1 模块 `apps/api/productdirector_api/batch.py`

| 能力 | 实现与诚实边界 |
| --- | --- |
| 矩阵展开 | `产品版本 × 计划版本 × Profile 版本 × variations`；响应同时给出**总数与逐项明细**，避免 `count=6` 的歧义；单次上限 **100 项**，超限 422 并给出实际数量 |
| 模式互斥 | 矩阵字段与 `items[]` **同时提交直接 422**（`matrix_and_items_exclusive`），不做隐式取舍 |
| 相容性 | 已批准计划绑定固定产品版本；任何不相容组合让**整次提交 422** 并逐条列出冲突（计划 id / 产品版本 / 原因），不允许偷偷替换产品或悄悄少生成几项 |
| 去重提示 | 相同输入/配置/种子 → `duplicates[]` 提示（**不自动合并**）；确认重复生产需给不同 `request_item_key` |
| 缓存键 | 产品版本 + 计划 + Profile 版本 + 变体 + 后期模板版本 + 种子 → `cache_key`（同键可复用 Master，决定重算范围） |
| 状态聚合 | 批次状态 `DRAFT/QUEUED/RUNNING/PAUSED/WAITING_REVIEW/COMPLETED/PARTIAL_FAILED/FAILED/CANCELLED`；`summarize()` 的 `total` **来自服务端**，不从客户端分页推算；发布状态单独表达 |
| 重试选择 | `select_retry_targets()` **只挑失败/已取消项**；已成功项保持不动（复用需输入快照/能力/许可完全相符） |
| 发布意图 | `auto_publish` 默认 false，仅表达意图；不跳过平台授权/审批/可见性确认 |

### 1.2 API

| 方法与路由 | 行为 |
| --- | --- |
| `POST /api/v1/batches/preview` | 只展开与校验，**无副作用**（明确返回 `side_effects: none`） |
| `POST /api/v1/batches` | 202 创建；`idempotency_key` 复用同一批次；按并发上限为 PENDING 项创建**独立 Run**（每项独立失败/取消，互不影响） |
| `GET /api/v1/batches`、`GET /batches/{id}`、`GET /batches/{id}/items` | 列表 / 聚合 / 分页项（`next_cursor` + 服务端 summary） |
| `POST /batches/{id}/pause` | **只停新调度**：已在跑的任务保持运行（取消需显式 cancel） |
| `POST /batches/{id}/resume` | 恢复调度并立即推进 |
| `POST /batches/{id}/cancel` | 范围可选 `not_started` / `all_unfinished`；已成功产物保留；取消后**重算聚合状态** |
| `POST /batches/{id}/retry-failed` | 只重置失败/取消项并重新调度，返回 `retried[]` 与 `skipped_succeeded[]` |

新增表：`batches`、`batch_items`（SQLite 内联 schema 与 `db/schema.postgres.sql` 同步）。

## 2. 真实缺陷（全部由真机验证暴露）

1. **批次项从未被执行**：`start_batch_item_run` 只写了 `jobs`/`runs`，没有写 **`run_jobs` 队列行**；Worker 只从 `run_jobs` 领取任务（`claim_job` 就是 `run_jobs JOIN jobs`），所以批次项永远停在 QUEUED。修复后新增测试断言「队列行存在且可被领取」。
2. **外键顺序**：`runs.job_id` 有外键指向 `jobs`，先插 `runs` 再插 `jobs` 在 SQLite 下侥幸通过、在 PostgreSQL 直接拒绝；已改为先写 `jobs` 再写 `runs`，并加测试校验引用完整性。
3. **`job_events` 并发序号冲突**（影响所有并发渲染，不只是批次）：执行器与租约心跳同时计算 `MAX(sequence)+1`，在 PostgreSQL 唯一键 `(job_id, sequence)` 下撞键，**真实导致 15 秒广告渲染到 75% 失败**。改为有界重试并重算序号，新增 4 线程 × 8 事件并发测试（32 条事件序号连续、无丢失）。
4. **取消不更新聚合状态**：取消未完成项后批次仍显示 RUNNING；已在 cancel 内重算状态（`PARTIAL_FAILED` / `FAILED` / `CANCELLED`）。
5. **调度失败不可见**：某项建 Run 失败会中断整轮调度且不留痕迹；现在逐项捕获并把 `调度失败: …` 写进该项 `error`，其他项继续调度。
