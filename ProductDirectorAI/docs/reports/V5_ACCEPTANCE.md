## 4. 如实未完成（不宣布 V5 PASS 的原因）

1. **10 条有权使用的 10–30 秒参考片 + 人工标注夹具**：本轮真实重演使用的是 2–3.1 秒的合成/测试参考片；主规划要求 10 条许可素材，覆盖静止、横向运动、推近、遮挡、低照度、变帧率，并由人工标注硬切/转场/景别/主要运动。标注必须由人完成，执行侧不能代替。
   - 已就绪：摄取与分析链路、`evaluate_cuts`（±0.2s 容差 F1）、10 条合成夹具报告可作为回归基线。
   - 待办：提供 10 条授权参考片 → 人工标注 JSON → 运行 `evaluate_cuts` 出报告。
2. **浏览器人工走查**：V5-05 页面与这次重演对照均由 API/CLI 证据覆盖，但双栏播放与时间线的交互观感需负责人打开「参考重演」页确认（本环境无浏览器）。
3. **V3/V4 阶段门仍未复核**：`V3_ACCEPTANCE.md`（7 项）与 `V4_ACCEPTANCE.md`（5 项）草稿仍待负责人逐项判定；V5 的「V3 保真持续通过」结论建立在这些门之上。
4. **构图取景为启发式**：适配规划使用确定性机位族（V3-07 校准）与固定注视高度 0.21m（按 CC0 相机标定），不是按产品包围盒自适应求解；这是公开记录的 `changed_dimensions: composition`，不是测量结论。
5. **单目限制**：不恢复焦距/相机路径，运动类型为启发式推断；低照度与遮挡场景的检测能力未在真实素材上评估（依赖第 1 项素材到位）。

## 5. 本轮新增/修复的工程缺口（真实缺陷，非文档口径）

- 参考重演计划**此前无法启动渲染**：`PlanUpdate` 强制「恰好 3 镜头 + 总时长 5–8 秒」，与参考映射产生的 1–4 镜头、分数时长计划冲突。现改为按 `from_reference` 分支校验：镜头结构/时长必须与冻结映射逐项一致（新增 `_validate_from_reference_plan_snapshot`），V1 合同不变。
- 输出合同拆分：新增 `ReenactmentOutputSpec`（显式整帧 `frame_count` + 分数时长）与 `output_spec_for_plan` 分派；`OutputSpec` 字段与 V1 `ImagePreviewSpec` Schema 保持严格同步（合同漂移守卫测试通过）。
- 渲染器原写死「恰好 3 镜头、单镜头 ≥24 帧」，现支持 1–8 镜头、单镜头 ≥1 帧（V1 的 3 镜头约束仍在 API 层强制）。
- 末尾开放分段（`end_s = null`）此前静默按 1.0 秒处理；现按参考片实际时长求解（`30126cfe` 由错误的 24 帧纠正为真实 72 帧）。
- 子秒分段此前被 24 帧下限抬升，产生 2 帧/镜头误差（超出 ≤1 帧门）；现按量化整帧处理（RE1 第三镜头 0.917s → 22 帧，误差 −0.01 帧）。
- Strict QA 相邻帧轮廓/尺寸检查此前不识别镜头边界，硬切处误报伪影；现在按计划声明切镜豁免跨边界帧对，镜内检查保持。
- 引用追踪：严格 Run manifest 新增 `reference_recreation`（参考片/代理 sha256、分析修订与 hash、映射 hash 与完整映射快照），重演产物可溯源。
