## 3. 本次发现的问题

### 3.1 横向素材的 9:16 居中裁切会丢失边缘内容（待处理）

输入是 1024×802 的横向合成图，输出是 1080×1920 竖屏。当前实现是**居中裁切**，结果是：

- 图上四个细节放大窗与西班牙语标注被裁掉；
- 产品本体在顶部（浮动刀头）与底部也被切掉一部分。

对"产品居中拍摄的竖版照片"这没有问题；但对横向素材、或主体不在画面中央的素材，构图会不可控。这属于 A06 里的「尺寸 / 朝向 / 可拍摄视角确认」，需要在 V1 内补上（至少提供裁切锚点/构图确认），否则真实用户很可能拿到不想要的构图。

### 3.2 验收脚本的边界帧曾互相覆盖（已修复）

图片与 GLB 两条链路把边界帧写到同一个目录且同名，后跑的 GLB 会覆盖图片的帧文件。已在 `scripts/v1_cloud_acceptance.py` 中改为按链路加前缀，并把视频帧文件名带上链路名。

## 4. 本地 / 云一致性观察

| 项目 | 本机 | 云端 | 结论 |
| --- | --- | --- | --- |
| 技术参数 | 1080×1920 / 24fps / 144 帧 / 6.000s | 同 | 一致 |
| 分镜语义 | 85mm/24/72/48 写入 Manifest | 同 | 一致 |
| 同输入同环境重复运行 | — | 两次运行视频 SHA-256 完全相同 | 同环境确定性成立 |
| 跨环境字节 | 542,689 字节 | 500,573 字节 | **不同**：FFmpeg/x264 版本不同（8.0.1 vs 4.4.2），参数与语义一致 |

结论：一致性验收应以**技术参数与语义**为准，不能要求跨编码器版本字节级相同。
