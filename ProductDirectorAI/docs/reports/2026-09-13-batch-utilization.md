# 批次连续调度与场景流水线优化

## 真实问题

用户要求制作墨西哥 TikTok 20 条视频并提高云利用率。已创建 20 个不同的三场景 15 秒计划，使用现有修剪器单产品裁切作为参考，经批次预览确认 20 项、无重复，再建立原生批次，max_concurrent=1。

实测 RTX 4090 推理期间瞬时 GPU 100%、显存带宽 100%、显存 19696/24564 MiB、功耗 415.39 W。控制台 CPU 0% 不是 GPU 空闲的证据，也不代表每个阶段 GPU 均满载。

首条真实完成后发现独立问题：`advance_batch(execute_inline=True)` 只执行首轮已调度项；`execute_job` 没有外部 worker 的完成回调，后续项停在 PENDING。该部署未运行独立 worker 常驻服务，导致批次间空闲。

## 修改

- 内联批次执行完一轮后，迭代调用原调度器认领下一轮，保持现有并发、暂停、取消及幂等约束，不靠用户刷新推进。
- 场景生成仅预排下一段：当前段已生成并下载后，在 CPU 编码前把下一段加入 ComfyUI 队列。GPU 仍一次运行一个模型任务，CPU 编码可与下一段推理重叠。
- 编码失败/取消时只尝试删除本任务尚未运行的预排项，记录废弃 Provider ID；不调用全局 interrupt。已运行项的来源记录保留，恢复不重复提交成功片段。

## 测试与产物

- 场景与 API 相关测试 11 项通过，包含预排顺序、恢复幂等、失败时仅清理自己的预排项。
- 批次新增回归覆盖：无外部 worker tick 时持续推进六项，以及第一项完成后暂停不再调度。
- 首条 15 秒真实视频已下载并添加西语字幕；1080×1920、360 帧与本地哈希校验通过，抽帧字幕可读。其余项继续保持独立结果与视觉审核边界。

这些优化减少等待，不减少场景、时长、分辨率或模型步骤；没有声称吞吐量翻倍，也没有扩容或购买资源。批次及本地下载状态需以运行记录为准。

验证结果：场景测试 11/11、批次测试 22/22、前端 build 与 Sites 4/4 通过。取消测试固定未完成任务后验证取消，避免连续调度完成全部任务导致测试没有可取消对象。
