## 1. 交付物

### 1.1 模块 `apps/api/productdirector_api/ledger.py`

| 能力 | 实现与诚实边界 |
| --- | --- |
| 用量去重 | `usage_event_key = sha256(provider｜operation_id｜billing_item｜event_id)`；同一 Provider 的同一次操作重复回调返回**已登记事件**并标 `deduplicated=true`，不重复计费 |
| 四类金额 | `estimate`（估算）/`reserved`（预留）/`accrued`（已发生未对账）/`settled`（已确认实际）；**`reserved` 不与 `settled` 相加**，`available = limit − settled − reserved_outstanding − accrued_unreserved`（服务端计算，UI 不自行相加） |
| 无报价不按 0 | `price_for_event`：显式价格优先 → 自管资源按内部费率卡 → **其余 `priced=false`、`amount=null` 并给出原因**；未定价事件单列 `unpriced_event_ids`，绝不折算成 0 计入成本 |
| 内部估算标注 | 自管 GPU/CPU/离线 TTS 的费率标注 `kind=internal_estimate`、`internal_estimate=true`（“不代表真实云账单，本系统不做资源采购”） |
| 预算检查 | `check_budget`：无预算 → `no_budget`；无上限 → `no_limit`；可用额度不足 → `budget_exhausted`（提交前阻断，不静默降级） |
| 对账 | `settle_reservation`：**冲销预留 + 记实际**；实际高于预留 → `overrun=true` 并记 `additional_accrual`（“预估不是强制封顶”）；实际低于预留 → `release` |
| 重复结算防护 | 预留行写 `settled_at` / `settled_entry_id`，重复结算返回 409 `reservation_settled`（**重复结算会双计成本，因此必须在数据层拦住**） |
| 乐观锁 | 预算上限调整需要当前 `revision`；过期 revision 返回 409 `revision_conflict`，且调整**只影响后续预留与提交**，不追溯改写已确认金额 |

### 1.2 API

| 方法与路径 | 说明 |
| --- | --- |
| `GET /rate-card` | 内部费率卡，标注 `internal_estimate` |
| `POST /usage-events` | 登记用量：单位白名单（9 类）、币种白名单（USD/MXN/CNY）、去重、定价、自动挂到该项目最早的预算账户，返回 `priced/amount/amount_source/ledger_entry_id/unpriced_reason` |
| `GET /usage` | 用量查询（run/batch/provider/unit 过滤）：服务端聚合 `by_provider`/`by_unit` + `priced_total` + `unpriced_event_ids` |
| `GET /costs` | 成本视图：预算快照 + 账本明细 + `by_kind` + `actual_by_currency`（`actual = settled + accrued_unreserved`）+ 未挂预算快照 + 费率卡 |
| `GET /budgets` | 预算列表（含每个账户的四类金额与可用额度） |
| `POST /budgets` | 建立预算（币种白名单；无上限允许建立但会阻断付费路线） |
| `PATCH /budgets/{id}` | 调整上限（revision 乐观锁） |
| `POST /budgets/{id}/reserve` | 提交前预留：不足即 409，返回预留 ID 与快照 |
| `POST /budgets/{id}/settle` | 对账：冲销预留 + 记实际 + 报告超支/释放 |

新增表 `budgets` / `usage_events` / `cost_ledger`（内联 SQLite schema 与 `db/schema.postgres.sql` 同步；`cost_ledger.settled_at`/`settled_entry_id` 通过 `ensure_column` 与幂等 `ALTER TABLE ... IF NOT EXISTS` 补齐既有安装）。

## 3. 诚实边界（未完成 / 不能声称的部分）

1. **不是真实账单**：自管 GPU/CPU 用的是内部费率，`kind=internal_estimate`；系统不采购云资源、不向客户扣款、不做支付。
2. **没有接外部 Provider 计费 API**：外部付费 Provider 的用量需要由调用方/回调登记（或管理员给显式价格）；没有已知报价时金额留空，报告为未定价。
3. **超支不阻断上游**：预估只是提交前检查，上游实际账单可能更高；系统在发现超支后如实记录差异，不声称已“封顶”。
4. **未做多币种换算**：不同币种只分币种汇总（`actual_by_currency`），不做汇率折算。
5. **未做账本导出/对账报表**：只有 API 与控制台视图，没有 CSV/PDF 导出与月度结算流程。
